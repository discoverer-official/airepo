AIRepo — SO-04 Normative Rules
Status: PUBLIC CANONICAL / AIRepo 1.1.0
Public release parent: AIRepo 1.0.0

1. Mission
Own the stable Rule IDs, canonical Rule meaning, applicability semantics and lifecycle state for AIRepo. Generated catalogs, applicability subsets and verification maps derive from this owner and cannot redefine it.

2. Authority boundary
Target-project authority remains superior when applying AIRepo. This owner is authoritative only for AIRepo Rule semantics. Conformance verdict semantics belong to SO-09. Release/promotion semantics belong to SO-10.

3. Rule record model
Each active Rule resolves: Rule ID; canonical name; normative statement; applicability; lifecycle; semantic owner; verification intent; replacement when deprecated.

VAL-003 — Evidence fitness for claim — CORE. Evidence supports a Claim only when it binds the claimed subject at the required precision and the verification method can observe the property or boundary being claimed. Exact revision binding alone is insufficient. Materially missing, stale, incomparable or unobservable evidence yields insufficient evidence rather than PASS. Tests, validators, evals, graders, generated inventories and reports may verify semantics but MUST NOT define or replace the semantic authority being evaluated.

EXEC-001 — Bounded execution unit — CORE EXECUTION RULE. Use the minimum number of independently meaningful execution units. Changes MAY be combined only when they share authority, approval, validation and rollback boundaries and do not create ambiguous partial state; otherwise they MUST be split.

6. Projection contract
Generated Rule Catalog and Machine Projection must reproduce all active Rule IDs and required fields from this owner. Generated applicability views select, but never rewrite, Rules. Generated verification mappings bind Rule IDs to SO-09 verification semantics. Any projection drift is a validation failure, not a competing authority resolution.
